핵심 설계 원칙 — Clerkai 백엔드는 n8n에 데이터만 던집니다. 어디로 보낼지(Slack·Notion·Gmail)는 n8n이 결정. 새 채널을 추가해도 백엔드 코드를 수정할 필요가 없습니다.
실제 구현
백엔드 코드 — share.py
# backend/routers/share.py
# 사용자가 "Slack 전송" 버튼을 누르면 이 엔드포인트가 호출됨

@router.post("/share/slack")
async def share_to_slack(body: ShareRequest, current_user: User = Depends(get_current_user)):

    # 페이로드 구성
    payload = {
        "event":            "meeting_processed",
        "user_id":          current_user.id,
        "transcript_count": body.transcript_count,   # 발화 수
        "summary":          body.summary,             # AI 요약문
        "key_decisions":    body.key_decisions,       # 핵심 결정사항 []
        "action_items":     body.action_items,        # 액션아이템 []
    }

    # n8n Webhook으로 POST — Railway 환경변수 N8N_WEBHOOK_URL 사용
    async with httpx.AsyncClient(timeout=15) as client:
        resp = await client.post(N8N_WEBHOOK_URL, json=payload)

    return {"message": "Slack으로 공유되었습니다"}

n8n 설정
n8n 워크플로우 구성 방법
1
Webhook 트리거 노드
n8n Cloud에서 새 워크플로우 생성 → Webhook 노드 추가.
HTTP Method: POST / Path: 자동 생성 URL 복사
Node Type : Webhook
HTTP Method: POST
Path : /clerkai-meeting (또는 자동 생성)
→ Production URL 복사 → Railway N8N_WEBHOOK_URL 에 붙여넣기
2
Code 노드 — Slack 메시지 포맷
수신한 JSON을 Slack Block Kit 형식으로 변환하는 JavaScript 코드 작성.
// n8n Code Node (JavaScript) const data = $input.first().json; const decisions = data.key_decisions .map(d => `• ${d}`).join('\n'); const actions = data.action_items .map(a => `☐ ${a}`).join('\n'); return [{ json: { text: `📋 *회의록 요약* (발화 ${data.transcript_count}건)`, blocks: [ { type: "header", text: { type: "plain_text", text: "📋 회의록 요약" }}, { type: "section", text: { type: "mrkdwn", text: data.summary }}, { type: "divider" }, { type: "section", text: { type: "mrkdwn", text: `*핵심 결정사항*\n${decisions}` }}, { type: "section", text: { type: "mrkdwn", text: `*액션아이템*\n${actions}` }}, ] } }];
3
Slack 노드 — 채널 전송
Slack 노드 추가 → Slack OAuth 연결 → 채널 선택 → 이전 노드의 blocks 연결.
Node Type : Slack
Operation : Send a message
Channel : #회의록 (또는 DM)
Message Type : Blocks
Blocks : {{ $json.blocks }}
4
환경변수 연결 (Railway)
n8n Webhook URL을 Railway 환경변수에 등록해 백엔드와 연결.
railway variables set N8N_WEBHOOK_URL=https://your-n8n.cloud/webhook/clerkai-meeting railway redeploy --yes
확장성
n8n으로 더 추가할 수 있는 것
📝
Notion 자동 생성
Notion 노드 추가만으로 회의록 페이지 자동 생성. 백엔드 코드 수정 없음.
📧
Gmail 이메일 발송
참석자 이메일로 액션아이템 자동 발송. Gmail 노드 연결만 하면 됨.
🎫
Jira 티켓 자동 생성
action_items 배열을 순회하며 Jira 이슈 자동 생성. IF 노드로 조건 분기.
⏰
D+3 팔로업 알림
Wait 노드로 3일 후 자동 리마인더. "액션아이템 완료 여부 확인" Slack DM.
면접 준비
예상 질문 & 모범 답변
n8n을 왜 직접 Slack API 대신 사용했나요?
백엔드와 전달 채널을 분리하기 위해서입니다. 직접 Slack API를 호출하면 "Notion도 보내줘", "Teams도 추가해줘" 요청이 올 때마다 백엔드 코드를 수정해야 합니다. n8n을 중간에 두면 백엔드는 항상 같은 JSON 하나만 던지고, 어디로 보낼지는 n8n 워크플로우에서 노드만 추가하면 됩니다. 이게 마이크로서비스에서 말하는 단일 책임 원칙(SRP)을 자동화 레이어에 적용한 것입니다.
n8n 워크플로우를 직접 만들어보셨나요? 어떻게 구성했나요?
네, 3개 노드로 구성했습니다. ① Webhook 트리거 — Clerkai 백엔드에서 POST 요청을 받습니다. ② Code 노드 — 수신한 JSON(요약, 결정사항, 액션아이템)을 Slack Block Kit 포맷으로 변환하는 JavaScript를 작성했습니다. ③ Slack 노드 — 포맷된 메시지를 지정 채널로 전송합니다. n8n Cloud의 Webhook URL을 Railway 환경변수에 등록해서 백엔드와 연결했습니다.
Webhook이 뭔지 설명해줄 수 있나요?
"이벤트가 발생했을 때 지정된 URL로 HTTP 요청을 보내는 방식"입니다. 반대 개념인 폴링(polling)은 "5초마다 서버한테 변경사항 있어?"라고 물어보는 것이고, 웹훅은 "변경사항 생기면 너가 나한테 알려줘"입니다. Clerkai에서는 사용자가 Slack 전송 버튼을 누르는 순간 백엔드가 n8n Webhook URL로 POST를 날리고, n8n이 바로 Slack으로 전달합니다.
Channel.io에서 고객사 CS 자동화를 할 때 n8n을 어떻게 쓸 것 같나요?
Clerkai와 동일한 패턴입니다. ① 트리거 — Channel.io에서 상담 종료 이벤트 발생 시 Webhook 수신. ② 데이터 가공 — 상담 내용을 Code 노드에서 정형화. ③ 다중 출력 — Dify 지식베이스에 적재(학습 데이터 축적) + 담당자에게 Slack 요약 + CRM에 상담 내역 기록. 하나의 이벤트에서 세 가지 작업이 자동으로 분기되는 구조입니다. 고객사마다 원하는 출력이 다르기 때문에 n8n 워크플로우만 바꾸면 대응할 수 있습니다.
n8n vs Zapier 차이를 설명해줄 수 있나요?
n8n은 오픈소스고 코드 노드(JavaScript)를 직접 작성할 수 있어 복잡한 데이터 변환이 가능합니다. 자체 서버에 설치도 되고 비용이 저렴합니다. Zapier는 코드 없이 클릭만으로 연결하는 게 강점이고 6,000개 이상 앱이 연동됩니다. 대기업 현업팀이 주로 씁니다. 저는 개발자 친화적인 n8n으로 먼저 빌드하고, 고객사 현업팀이 직접 수정해야 한다면 Zapier로 마이그레이션하는 방식이 실용적이라고 생각합니다.
