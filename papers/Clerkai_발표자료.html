현장에서 반복 발견한 패턴
Pattern 01

담당자마다 다른 CS 처리 방식

같은 케이스도 처리가 다르다 → 표준화·매뉴얼화가 먼저. Channel.io가 말하는 "AI가 이해할 수 있는 지식으로 변환"과 정확히 같은 문제.

Pattern 02

정보 정리에 시간 쓰는 담당자

회의·상담 후 정리가 반복 비용 → 자동화로 없애야 할 작업. Clerk_AI의 출발점.

Pattern 03

비효율 발굴보다 실행이 느림

문제는 알지만 툴·기술 장벽으로 자동화 못 함 → 내가 직접 빌드하는 이유.

Clerk_AI 백엔드는 항상 같은 JSON 하나만 n8n으로 던집니다.
어디로 보낼지(Slack·Notion·Dify)는 n8n 노드만 추가하면 됩니다.

Feature Overview
Feature 01

실시간 STT

WebSocket 기반 실시간 음성 인식. 말하는 즉시 텍스트로 출력되며, 회의 도중 메모장과 나란히 확인 가능.

Deepgram nova-2
Feature 02

3개 AI 모델 비교

Llama 3.3 70B · Llama 4 Scout · Qwen3 32B를 동시에 실행. 속도, 토큰, 품질을 탭별로 비교.

Groq API · Free Tier
Feature 03

Cursor 스타일 탭

모델 A·B·C·비교·마인드맵 탭을 파일처럼 열고 닫으며, 좌우 패널 크기를 자유롭게 드래그 조절.

Split Panel
Feature 04

n8n Slack 자동화

요약·결정사항·액션아이템을 인라인 편집 후 n8n 워크플로우를 통해 Slack 채널로 원클릭 전송.

n8n Webhook
Feature 05

Dify 지식베이스

회의 완료 시 Dify 자동 적재. 사이드바에서 개별 전송, Settings에서 일괄 전송 지원.

RAG 검색
Feature 06

히스토리 · 테마

오늘·어제·이번 주·이전 그룹화 히스토리. 밝음/어두움/기기 3가지 테마 CSS 변수 전환.

SQLite · Light·Dark

Architecture

Channel.io 적용
이 역량을
Channel.io에서

Clerk_AI에서 쌓은 패턴 — 현장 관찰 → 비효율 정의 → n8n 설계 → Dify 적재 — 을
Channel.io 고객사 CS 자동화에 그대로 적용합니다.

Clerk_AI에서 한 것
Trigger
회의 종료 → 사용자 "Slack 전송" 클릭
Process
FastAPI → n8n Webhook POST
payload: summary / key_decisions / action_items
Output ①
n8n → Slack Block Kit 메시지
팀 채널로 회의록 자동 전송
Output ②
Dify 지식베이스 자동 적재
누적 회의록 → RAG 검색 가능
→
SAME PATTERN
Channel.io에서 할 것
Trigger
상담 종료 → Channel.io Webhook 이벤트
Process
n8n: 상담 내용 → 정형화 + 분류
카테고리 / 감정 / 해결 여부 태깅
Output ①
담당자 Slack DM — 요약 + 재연락 필요
미해결 건 자동 에스컬레이션
Output ②
Dify → 고객사 FAQ 지식베이스 갱신
"고객사 FAQ·상담·정책 → AI가 이해할 수 있는 지식으로 변환" — 공고 원문
