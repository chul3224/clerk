## 2. 문제 정의

### 현실의 고통

> **"1시간 회의 후 30분 회의록 작성"** — 국내 직장인 평균 회의 후 정리 시간

- 회의 중 메모에 집중하면 대화에 집중 못함
- 회의 후 기억에 의존한 정리는 누락과 오류가 발생
- 누가 무슨 말을 했는지 추적이 어려움
- 액션아이템이 흐지부지되는 경우가 많음
- 회의록 작성 자체가 귀찮아서 아예 안 하는 경우도 빈번

### 핵심 Pain Point 3가지

| # | Pain Point | 영향도 |
|---|-----------|--------|
| 1 | 회의 후 정리에 드는 시간 낭비 | 상 |
| 2 | 화자별 발언 내용 추적 불가 | 중 |
| 3 | 요약 품질이 사람마다 다름 | 중 |

## 3. 해결 방안

### 핵심 솔루션

```
음성 녹음 1개
    ↓
자동 텍스트 변환 (Whisper STT)
    ↓
화자 분리 (Pyannote.audio)
    ↓
인물별 대화록 저장
    ↓
AI 요약 — 2가지 모델 동시 비교 출력
(Llama 3.1 8B vs GPT-OSS 120B)
```

### 차별화 포인트

1. **화자 분리 자동화** — 누가 무슨 말을 했는지 자동 태깅
2. **듀얼 모델 비교** — 오픈소스 LLM 2종의 요약 품질/속도 실시간 비교
3. **수동 이름 태깅** — 자동 분리 후 Speaker A → 실제 이름으로 수정 가능
4. **즉시 다운로드** — 정리된 회의록 `.txt` / `.md` 저장

## 4. 서비스 구조 및 기능 명세

### 프로토타입 범위 (v1.0)

#### 기능 1 — 음성 입력
- 파일 업로드 (`.mp3`, `.wav`, `.m4a`, `.webm`)
- 실시간 브라우저 녹음 (Web Audio API)
- 최대 파일 크기: 25MB (Whisper API 제한)

#### 기능 2 — STT 변환
- Whisper API 활용 음성 → 텍스트 변환
- 타임스탬프 포함 출력
- 지원 언어: 한국어 / 영어

#### 기능 3 — 화자 분리
- Pyannote.audio 활용 자동 화자 분리
- 지원 인원: 2~4인 (프로토타입 기준)
- 출력 형태: `Speaker A / Speaker B / ...`
- 수동 이름 태깅 UI 제공 (Speaker A → "홍길동")

#### 기능 4 — 대화록 저장
- 화자별 발언 내용 타임스탬프와 함께 저장
- 형태 예시:
  ```
  [00:00:05] 홍길동: 오늘 회의 시작하겠습니다.
  [00:00:12] 김철수: 네, 안건 먼저 공유드릴게요.
  ```
- `.txt` / `.md` 다운로드 지원

#### 기능 5 — AI 요약 (듀얼 모델 비교)
- Groq API 활용 (Llama 3.1 8B / GPT-OSS 120B)
- 동시 처리 후 나란히 비교 출력
- 비교 컨셉: **초고속 경량 모델(Llama 8B) vs 고성능 오픈소스 모델(GPT-OSS 120B)**
- 출력 항목:
  - 회의 핵심 요약 (3~5줄)
  - 주요 결정 사항
  - 액션아이템 (담당자 포함)
- 비교 지표 자동 측정:
  - 응답 속도 (ms)
  - 출력 토큰 수
  - 액션아이템 추출 개수

## 5. 기술 스택

### 프론트엔드

| 기술 | 용도 | 선택 이유 |
|------|------|----------|
| React (Vite) | UI 프레임워크 | 빠른 개발, 컴포넌트 재사용 |
| Tailwind CSS | 스타일링 | 빠른 UI 구성 |
| Web Audio API | 브라우저 녹음 | 별도 설치 없이 녹음 가능 |
| Cloudflare Pages | 배포 | 무료, 빠른 배포 |

### 백엔드

| 기술 | 용도 | 선택 이유 |
|------|------|----------|
| FastAPI (Python) | API 서버 | 비동기 처리, 빠른 개발 |
| Whisper API | STT 변환 | 한국어 정확도 높음 |
| Pyannote.audio | 화자 분리 | 오픈소스, HuggingFace 연동 |
| Groq API | LLM 추론 | 오픈소스 모델 + 빠른 속도 |
| Railway / Render | 백엔드 배포 | 무료 티어 제공 |

### AI 모델

| 모델 | 제공 | 역할 |
|------|------|------|
| Whisper large-v3 | OpenAI / Groq | 음성 → 텍스트 |
| Pyannote 3.0 | HuggingFace | 화자 분리 |
| Llama 3.1 8B | Meta / Groq | 회의록 요약 A (초고속 경량) |
| GPT-OSS 120B | OpenAI / Groq | 회의록 요약 B (고성능 오픈소스) |

## 6. 시스템 아키텍처

```
[사용자 브라우저]
│
│  ① 음성 파일 업로드 or 실시간 녹음
│
▼
[Cloudflare Pages - React 프론트엔드]
│
│  ② 음성 파일 전송 (FormData)
│
▼
[FastAPI 백엔드 - Railway/Render]
│
├── ③ Whisper API → 전체 텍스트 + 타임스탬프
│
├── ④ Pyannote.audio → 화자 분리
│       Speaker A: 0:00~0:15
│       Speaker B: 0:15~0:32
│
├── ⑤ 타임스탬프 매칭 → 화자별 대화록 생성
│
└── ⑥ Groq API 병렬 호출
        ├── Llama 3.1 8B → 요약 결과 A
        └── GPT-OSS 120B → 요약 결과 B
│
▼
[프론트엔드 결과 출력]
├── 화자별 대화록 (수동 이름 태깅 UI)
├── 모델 A / 모델 B 요약 비교
├── 속도 / 토큰 수 비교 지표
└── 다운로드 버튼 (.txt / .md)
```

## 7. UI/UX 흐름

- 앱 소개 + 시작하기 버튼
- 파일 업로드 드래그앤드롭 영역
- 또는 실시간 녹음 버튼

### Step 2 — 처리 중 화면
- 진행 상태 표시 (STT → 화자분리 → 요약)
- 예상 소요 시간 표시

### Step 3 — 결과 화면

│  김철수: 안건 공유드릴게요.              │
├──────────────────┬──────────────────────┤
│  🤖 Llama 3.1   │  🤖 GPT-OSS 120B     │
│  요약: ...       │  요약: ...           │
│  액션아이템: ... │  액션아이템: ...     │

## 8. 모델 성능 비교 전략

### 비교 항목

| 항목 | 측정 방법 |
|------|----------|
| 응답 속도 | API 호출 시작 ~ 응답 완료 (ms) |
| 요약 길이 | 출력 텍스트 글자 수 |
| 액션아이템 수 | 추출된 항목 개수 |
| 토큰 사용량 | Groq API 응답값 활용 |

### 비교 의도

단순 기능 구현을 넘어 **"어떤 모델이 어떤 상황에서 더 적합한가"** 를 데이터로 분석하는 PM/개발자 관점의 의사결정 근거 제시

## 📌 프로젝트 의의

이 프로젝트는 단순한 기능 구현을 넘어:

1. **비즈니스 문제 정의** → 실무 Pain Point에서 출발
2. **AI 워크플로우 설계** → STT → 화자분리 → LLM의 파이프라인 설계
3. **데이터 기반 의사결정** → 두 모델의 성능을 수치로 비교
4. **확장성 고려** → 프로토타입 → 풀서비스로의 로드맵 제시

**AX(AI Experience) PM으로서의 문제 정의 → 솔루션 설계 → 배포 → 고도화** 역량을 실증하는 포트폴리오입니다.
